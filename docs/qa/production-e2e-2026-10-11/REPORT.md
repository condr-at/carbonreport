## Найденные и исправленные дефекты

| Дефект | Наблюдение / причина | Исправление |
| --- | --- | --- |
| Чужое имя проекта в SSR | Автоматический сценарий: API возвращал 403, но исходный HTML страницы содержал имя чужого проекта | Summary и dataset проверяют membership и организацию до чтения; недоступный проект даёт 404 |
| Преждевременная отправка анкеты | В production после предпоследнего «Далее» последний блок кратко появлялся и маршрут переходил к выбору отчётов | Отмена native default action у навигационных кнопок и разные keys у Next/Submit |
| Ложное «письмо отправлено» | Код игнорировал `Resend.error`, а register UI всегда показывал `sent`; исключение почты могло вернуть 500 после создания пользователя | Явный результат отправки; успешная регистрация сохраняет 201 и сессию при недоставленной почте, resend возвращает 503 |
| Неясное продолжение регистрации | При активной сессии страница предлагала только повторное письмо и возврат ко входу | Кнопка Continue to workspace и явный статус почты |
| Verification token в логах | Проверка исходников выявила логирование токена и claims | Удалены чувствительные логи; редиректы не переносят входные query-параметры |

## Автоматизация и границы

Добавлены `npm run test:e2e`, `test:e2e:guards` и GitHub Actions workflow. E2E использует отдельную локальную PostgreSQL `*_e2e_test`, явное разрешение reset, отдельный порт и копию исходников без `.env`; production-сброс технически отклоняется. Реальная почта в CI отключена.

Локально итоговый запуск: safety guards 2/2, неизменённый существующий sanity script 120/120, production build и TypeScript успешны; browser E2E 6/6. Сценарий проверяет регистрацию, организацию, продукт, ZIP, ошибки, persistence, API/HTML изоляцию и финальный блок анкеты. Сохранён также первоначальный неуспешный результат, обнаруживший SSR-утечку. Облачный [GitHub Actions 38138480585](https://github.com/condr-at/carbonreport/actions/runs/38138480585) также успешен: guards 2/2, sanity 120/120, build, browser 6/6. [Метаданные](github-actions.json), [полный лог](github-actions.log), [локальные доказательства](local-ci/provenance.json). В сохранённых логах нормализованы завершающие пробелы; исходные локальные логи остаются в игнорируемой `.artifacts`.

Исправления опубликованы обычным Git push `f1a8af0`: [Vercel production READY и назначенные домены](deployment.json). После публикации второй аккаунт создан через UI на предоставленном адресе; проверены новый экран `not_sent`, Continue to workspace и экран первого workspace. Email и пароли в репозиторий не сохранены. Реальная отправка не состоялась: read-only запрос к Resend с production-ключом вернул HTTP 400, `validation_error`, `API key is invalid`; [безопасная диагностика](mail-diagnostic.json). Временная копия production env удалена. Пользователю предложено заменить ключ через Resend/Vercel; после этого необходимы redeploy, resend, получение письма и переход по ссылке. [Справочник ошибок Resend](https://resend.com/docs/api-reference/errors).

Production проверка изоляции после исправления: [9/9 HTTP/HTML проверок](production-access-checks.json), три чужих URL дают 404 и не содержат закрытые значения; JSON/ZIP возвращают 403. Прямой URL чужого отчёта дополнительно открыт в браузере и показал Page not found ([скриншот](10-outsider-404.png)). Проверки не закрывают reset/refresh, все роли и приглашения, остальные 47 форм отчётов, нормативную приёмку или полный REL-01.

Технические оговорки: CUA-заполнение нативного date input потребовало реального клавиатурного изменения для React state; это ограничение инструмента, не объявленный баг продукта. Ожидание download event завершилось тайм-аутом, но браузер показал успешное скачивание; фактический файл из Downloads проверен по новым projectId/reportId/version. Повторное API-скачивание не выдаётся за браузерное.
