# Проверка Carbon Report в браузере

Дата: 2026-10-10. Статус: завершено. Найденные воспроизводимые ошибки исправлены; ограничения и предложения перечислены отдельно.

## Вывод

Основной путь «аккаунт → организация → проект → данные → запрос поставщику» работает после исправлений. До исправлений были потеря несохранённых данных при перезагрузке, чтение контактов/запросов чужих организаций, неисправное восстановление удалённого проекта и блокирующие ошибки мастера. Продукт пока не даёт законченного пути к обещанному экспортируемому отчёту: экран отчёта остаётся рабочей таблицей, Files — заглушка, запросы требуют ручного email-клиента.

Бизнес-план расположен отдельно: [business-planning](../../business-planning/README.md). Приоритетные предложения без реализации вынесены в [FLOW_IMPROVEMENTS.md](FLOW_IMPROVEMENTS.md).

## Метод и среда

Сценарии выбраны по задачам нового пользователя и фактическому интерфейсу. Существующая документация пользовательских сценариев не использовалась как эталон. Сначала наблюдался интерфейс и сохранялись скриншоты, затем точечно проверялся код.

- Chrome, отдельная вкладка, desktop 1620 × 808, локальный Next.js. Встроенный браузер недоступен.
- Тестовый аккаунт `qa.browser.20261010@example.test`; организации `QA Carbon Metals` и `QA Switching Workspace`. Только синтетические изменения в `carbonreport_dev`; исходные записи других организаций не изменялись.
- Автоматические интеграционные тесты используют отдельную `localhost/carbonreport_test`, подтверждённую перед очисткой тестовых таблиц.
- Исходные зависимости зависали при чтении файлов (`ECANCELED`, системный sample показал ожидание `read`). Для браузера использована копия текущего исходного кода `/tmp/carbonreport-qa-runtime`, установка строго по lockfile, Node 20.20.0. Причина File Provider/iCloud вероятна, но не доказана; настройки системы и исходные зависимости не менялись.
- Исправления находятся в исходном репозитории и перенесены в runtime. Пользовательские незакоммиченные изменения сохранены. Коммитов, публикации, настоящих рассылок и платежей нет.
- При первом запуске копии отсутствовал `middleware.ts`; это исправлено до основного прохода. Скриншот 02 не считается самостоятельным доказательством ошибки исходного приложения.

### Отклонённое подозрение

Deadline сначала отображался как `—` (18). Повтор установил, что инструмент `fill` менял DOM native date input без обновления React-state. После реального клавиатурного изменения ArrowUp дата появилась в подтверждении и сохранилась в таблице как 21 октября 2026. API/БД roundtrip тоже проходит. Рабочий код deadline не изменялся; это не записано как исправленный баг продукта. Отображение date-only как «2:00 AM» оставлено отдельным UX-предложением.

## Автоматическая проверка

- Исходная база: integration 65/65, sanity 39/39, TypeScript без ошибок.
- После исправлений: integration **70/70**, sanity **61/61**, TypeScript без ошибок. Новые queue/access/bulk/cache-регрессии включены в стандартные `test:sanity` и `test:unit`, а не оставлены только ручной командой.
- Scoped ESLint: 0 ошибок; два прежних unused-variable предупреждения в project-layout и projects API. Не запускался полный lint всех посторонних файлов.
- Retention: 4/4 точечных проверки граничных дат.
- Сохранённые доказательства: [команды, среда и итоги](evidence/summary.txt), [sanity](evidence/sanity-final.log), [integration](evidence/integration-final.log), [retention](evidence/retention-regression.log). JWT и потенциальные реквизиты подключения в копиях логов редактированы.
- Финальная сверка 376 файлов исходников/runtime обнаружила один не перенесённый защитный `typeof` в visibility helper. Он перенесён, затронутые 11 тестов decision-engine повторно прошли. Последующая сверка — 0 различий.
- Проверка whitespace затронутого кода чистая. Полный `git diff --check` дополнительно отмечает прежние два пробела Markdown line break в `docs/README.md:11`; они не исправлялись.

## Решения и итоговое состояние

- Обходить проблему чтения исходных зависимостей изолированным runtime; не менять File Provider/iCloud и не удалять исходные файлы.
- Чтение Contacts/Requests ограничено всеми доступными пользователю организациями. Ограничение именно текущей выбранной организацией — отдельное UX-решение, не обход защиты.
- Не строить новые экспортные движки, оплату или file storage внутри аудита; отсутствующие функции вынесены в предложения.
- Бюджет доказательств расширен с 30 до 36 скриншотов (до 30 МБ) из-за дополнительно обнаруженных ошибок изоляции и восстановления; один основной проход и повторы затронутых сценариев.
- Повторы инвалидации запросов, свежего мастера, очереди сохранения и прогресса пройдены. Сохранено 34 скриншота; весь каталог доказательств около 2.2 МБ.
- В локальной БД оставлены QA Carbon Metals с активным QA Aluminium Profile и синтетическими запросами, QA Switching Workspace без проектов. QA Keyboard Retest находится в обратимом DELETED после повторной проверки удаления; его восстановление с сохранением данных проверено. Черновик QA Fresh Wizard Check закрыт через Leave wizard.
- Runtime сохранён в `/tmp/carbonreport-qa-runtime` для локального воспроизведения; он использует уже существующую dev-БД. Это временное окружение не является отдельной версией исходников.

## Пределы проверки

Не проверены доставка реального email, внешнее хранилище, платежи, реальные приглашения участников, соответствие CBAM/ISO, все типы отчётов и мобильная вёрстка. Проверка подтверждает перечисленные локальные сценарии, а не production readiness всего продукта.
