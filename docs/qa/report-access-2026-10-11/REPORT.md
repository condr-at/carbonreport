# Проверка доступа к API отчёта

Дата: **2026-10-11**. Статус: исправление написано и проверено локально. Это точечное продолжение [браузерного аудита](../browser-audit-2026-10-10/REPORT.md), не новый полный аудит безопасности или браузерный E2E.

## B16 — чтение чужого отчёта по известным ID

При проверке готовности архитектуры найден пропуск проверки доступа в `GET /api/projects/[id]/reports/[reportId]`: маршрут проверял принадлежность отчёта проекту, но не членство текущего пользователя в организации. Общий middleware проверяет вход; одного входа недостаточно для доступа к чужому проекту.

Воспроизведение: отдельный тест вызывает настоящий route с авторизованным пользователем без членства и известными ID; на границе Prisma используются синтетические записи. До исправления ответ **200 вместо ожидаемого 403**, включая данные отчёта. [Падающий тест](evidence/report-authorization-red.log) и [точный маршрут до исправления](evidence/report-route-before-authorization.ts.txt) сохранены. Доступ к реальным чужим данным не выполнялся.

## Изменение

- `getCurrentUser()` вызывается до чтения БД.
- Общий `requireProjectForDataset` проверяет доступ с минимальной ролью VIEWER_READONLY, принятое членство, состояние организации и проекта до чтения dataset отчёта.
- Поиск отчёта ограничен парой `reportId + projectId`; подстановка чужого reportId в разрешённый проект возвращает 404.
- Ошибки используют общий структурированный формат; успешный JSON сохраняется, ответ помечен `private, no-store`.
- Новый regression test включён в стандартные `test:sanity` и `test:unit`.
