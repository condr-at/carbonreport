# Следующие улучшения флоу supplier package

Наблюдения 2026-10-11 при реальном проходе интерфейса. Это предложения, не выполненные изменения и не отдельный backlog; приоритеты и статусы находятся в [рабочем плане](../../planning/BACKLOG.md).

1. **После создания организации вести к первому продукту.** Сейчас пользователь попадает в настройки и должен сам перейти в Projects. Предложение: заметное действие «Create your first product» с сохранением доступа к настройкам.
2. **Выбирать источник по названию документа.** Сейчас Emissions просит evidence ID раньше заполнения реестра. Предложение: добавить источник прямо рядом со значением и выбирать существующий документ из списка; технический ID оставить в данных.
3. **Показывать сравнение версий при конфликте.** Потеря данных предотвращена и черновик сохранён, но пользователь вручную копирует свои правки перед Reload. Предложение: показать сохранённое и своё значение рядом, выбирать по полям. Для этого нужен явный контракт merge, а не автоматическая перезапись.
4. **Отделить клиентские вопросы от технических проверок.** В форме и HTML предупреждения понятны, но повторяются; реестр источников и справочные ID перегружают сводку. После приёмки получателем согласовать компактную первую страницу и отдельный технический appendix, сохранив обязательные оговорки и provenance.
5. **Согласовать фактический комплект передачи.** ZIP содержит ссылки; исходные документы получатель пока получает отдельно. На пилоте выяснить, требуется ли безопасная ссылка, вложения, workbook получателя или ручная проверка консультанта. Наличие Files tab не означает готовность этих функций.
6. **Проверить доступность на малом экране и печать.** Desktop-проход выполнен, мобильный viewport, screen reader и печатные переносы многостраничного HTML не проверялись. Принимать их по конкретному формату доставки пилота.

Уже исправлено в этом срезе: направление Overview в нужную форму, честная подпись field coverage, восстановление черновика, ссылка reload при конфликте, доступные подписи создания организации и читаемый реестр evidence в HTML. [Доказательства](REPORT.md).
