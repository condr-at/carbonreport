# CBAM supplier review package: контракт профиля 1.0

Проверено по библиотеке первичных источников 11 октября 2026 года. Реализация: `src/lib/cbam/supplier-package.ts`; идентификатор профиля `cbam-supplier-review/1.0`.

## Назначение и граница обещания

Это собственный пакет данных для проверки получателем: один продукт, одна производящая установка, один календарный год производства начиная с 2026 года. Это не обязательный operator emissions report, его summary, CBAM declaration, подача в Registry или заключение верификатора. В текущем профиле 34 поля. Условия готовности ниже являются правилами нашего продукта, а не утверждением, что законодательство требует именно эти поля или такой файл.

`isReady` означает только отсутствие ошибок комплектности и формата для передачи на проверку. Значения actual/default/mixed, классификация CN и наличие верификации заявлены пользователем. Приложение не проверяет достоверность документов, юридическую применимость, аккредитацию или методику. Статус `declared_verified` всегда сопровождается предупреждением; статус `not_verified` допускает готовность к проверке. Для регуляторного использования actual values необходимо отдельно установить соответствие требованиям к верификации. [TR25, с. 14–15]

Полный актуальный обязательный operator workbook в ограниченном исследовании не получен. Наличие собственного экспорта не заменяет официальный шаблон. Сохранённый исторический шаблон переходного периода 2024 года нельзя представлять шаблоном definitive period 2026.

## Данные профиля

- Получатель, составитель и роль поставщика; для trader отдельно требуется юридическое наименование поставщика. Наименование и контакт производящего оператора не заменяются данными трейдера.
- Установка: имя, физический адрес и страна; существующий идентификатор установки необязателен и не доказывает регистрацию.
- Год производства и фактические даты покрытия в его пределах, не позднее даты проверки. Неполное покрытие помечается provisional / YTD. `full` означает лишь даты 1 января — 31 декабря, а не подтверждённую полноту мониторинга.
- Один продукт, заявленный восьмизначный CN, пользовательский статус проверки CN, описание процессной границы/атрибуции и явное описание включения релевантных прекурсоров.
- Сообщённый direct SEE в `tCO2e/t_goods`, его заявленная основа actual/default/mixed и ID доказательства. Indirect SEE сообщается отдельно, если выбран `reported`; для `not_applicable` требуется объяснение, а `unknown` блокирует готовность.
- Для каждого активного default/mixed компонента — точный источник, версия, строка таблицы и учёт markup. Запись строки должна позволять проверить страну, товар/прекурсор, год и назначение значения; приложение этого не выводит автоматически. Возможны несколько записей для одного компонента. CN прекурсора не обязан совпадать с CN конечного продукта. [TR26, с. 113–117; TR27]
- Реестр доказательств: `id`, `title`, `reference`, `version`, `period`, `owner`, `disclosure`. Это ссылки, а не вложенные или проверенные документы. При заявленной верификации дополнительно требуются идентификация верификатора и ID доказательства.

## Допустимая арифметика

Входные SEE уже сообщены оператором/поставщиком в поддерживаемой единице и должны включать релевантный вклад прекурсоров в заявленных границах. Приложение не выводит SEE из топлива, энергии, факторов, суммарных выбросов или распределения между продуктами. Не выполняются пересчёт функциональных единиц, выбор defaults или начисление markup.

Необязательная масса партии в тоннах используется только для двух независимых иллюстративных произведений:

```
directLotEmissions = lotMassTonnes × reportedDirectSEE
indirectLotEmissions = lotMassTonnes × reportedIndirectSEE  // лишь если reported
```

Нет суммы direct + indirect, дополнительной суммы прекурсоров, расчёта сертификатов или утверждения о регуляторных выбросах импортированной партии. При ошибках валидации вычисленные выбросы отсутствуют. В расчётах используются конечные неотрицательные числа; переполнение блокирует готовность.

Методические требования не сводятся к этим произведениям: для реального определения SEE нужны соответствующие процессные границы, весь относящийся к процессу выпуск, правила атрибуции, релевантные прекурсоры и допустимые источники данных. Масса потреблённых прекурсоров и масса прекурсора в конечном продукте не взаимозаменяемы. Особые правила электроэнергии и функциональных единиц для отдельных товаров не реализованы. [TR26, с. 19, 22, 34–36]

## Валидация, черновик и экспорт

Пустое значение и буквальное «unknown» не превращаются в ноль. Ноль допустим. Проверяются существование даты, порядок дат, совпадение года, отсутствие будущего периода, восемь цифр CN, поддерживаемая единица, конечные числовые значения, условная комплектность, уникальность ID и разрешение ссылок на доказательства. Проверка CN — только синтаксическая; она не устанавливает включение товара в CBAM или Annex II. [TR01; TR25]

Черновик сохраняет невалидные строки. Merge принимает только известные поля и сохраняет остальные корневые ключи, datapoints и метаданные существующих значений. Неоднозначные дубликаты или repeatable datapoints для скалярного поля требуют разрешения и не перезаписываются молча. `isPackageFieldActive` задаёт одинаковую активность для интерфейса, содержательной валидации и экспорта: неактивные условные строки сохраняются в наборе данных, но не являются утверждениями активного пакета.

Человеческая проверка остаётся обязательным шагом использования результата: классификация и применимость; период и границы процесса; источники/предпосылки SEE; включение прекурсоров без двойного счёта; применимость indirect; корректная таблица defaults, строка и markup; scope и аккредитация заявленного верификатора; право передать доказательства получателю. Это checklist данного продукта, не универсальная юридическая форма.

## Первичные источники

Идентификаторы соответствуют `docs/report-reference/research/trade-transport.json`.

- **TR01 — European Commission, CBAM definitive regime:** https://taxation-customs.ec.europa.eu/carbon-border-adjustment-mechanism/cbam-definitive-regime_en
- **TR02 — European Commission, CBAM legislation and guidance:** https://taxation-customs.ec.europa.eu/carbon-border-adjustment-mechanism/cbam-legislation-and-guidance_en
- **TR25 — Guidance No. 2, Quick guide for non-EU operators:** https://taxation-customs.ec.europa.eu/document/download/91e1056c-4524-4705-aaa7-e25c1439a87a_en?filename=Guidance%20No.%202%20-%20Quick%20guide%20for%20non-EU%20operators%20on%20CBAM%20implementation.pdf
- **TR26 — Guidance No. 3, Methods for calculation of embedded emissions:** https://taxation-customs.ec.europa.eu/document/download/29b9eec7-1a4b-4eb6-ab85-96a0c9e35fd0_en?filename=Guidance%20No.%203%20-%20CBAM%20methods%20for%20the%20calculation%20of%20emissions%20embedded%20in%20goods.pdf
- **TR27 — Corrected definitive default values:** https://taxation-customs.ec.europa.eu/document/download/1c05d211-80cb-4aaa-8ef0-e08005a95d7e_en?filename=DV%20correcting%20act_final%20update_06.08.xlsx

Guidance объясняет применение норм, но не заменяет регламенты из актуального перечня TR02. На дату проверки каталог содержит definitive guidance от 14 августа 2026 года, методы по Implementing Regulation (EU) 2025/2547 и исправленные default values; сохранение версии входного источника остаётся ответственностью составителя пакета.
