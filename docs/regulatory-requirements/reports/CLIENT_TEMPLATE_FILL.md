# CLIENT_TEMPLATE_FILL — Client Questionnaire Preparation

Проверено: **2026-10-11**. Категория: `client_defined`. Семейство: Client-defined forms.

Карточка первичного сбора, а не заключение о соответствии. Требования и трактовки ещё нужно превратить в проверенный набор правил выбранной версии.

## Статус и применимость

Универсальной нормативной формы нет: источником требований будет версия файла/портала конкретного заказчика.

Только после получения формы, инструкции и условий передачи данных клиента.

## Выдаваемый результат

Заполненный исходный шаблон без потери структуры; список незаполненных/неприменимых полей и evidence.

## Входные данные

- Файл или схема заказчика, версия, язык, срок
- Словарь полей и разрешённые значения
- Границы, единицы, периоды, источники
- Согласованные правила для неизвестных значений

## Проверки и контрольные вопросы

Это требования и контрольные вопросы для данного типа; наши UX/инженерные проверки не становятся нормативными обязанностями. Реализованное покрытие и оставшиеся ограничения указаны ниже.

- Блокировать финальный выпуск без закреплённой клиентской формы; это наша рекомендация по контролю качества.
- Не менять идентификаторы/типы полей и не заполнять неизвестное нулём; проверить импорт получателем (наш контроль).
- Не предполагать, что PACT нужен всем клиентам [CE01].

## Проверка человеком

- Заказчик подтверждает mapping и полученный файл; неоднозначные вопросы возвращаются ему.

## Риски текущего интерфейса и пробелы реализации

- Нельзя обещать автоматическое заполнение любой формы без её образца.
- В коде статический общий dataset; нет пользовательского контракта формы и round-trip теста.
