# ТЗ-3: UI Project Creation Flow (Визард создания)

**Статус:** Черновик
**Дата:** 29.11.2025
**Приоритет:** Средний (Зависит от ТЗ-1 и ТЗ-2)

## 1. Цель
Обновить пользовательский интерфейс создания проекта, чтобы он соответствовал новой логике разделения на Corporate/Product и предотвращал ошибки выбора несовместимых отчетов.

## 2. Текущие проблемы
*   Пользователь сразу попадает на выбор отчетов без контекста.
*   В списке отчетов смешаны продуктовые (CBAM) и корпоративные (CSRD) стандарты.
*   Нет явного выбора типа проекта.

## 3. Технические требования

### 3.1. Новый Шаг 1: Выбор контекста
Файл: `src/app/projects/new/page.tsx` (или новый компонент)

1.  **Дизайн**:
    *   Две большие кликабельные карточки (Cards):
        *   **Организация (Corporate)**: Иконка здания. Описание: "Отчетность по всей компании (Scope 1, 2, 3), CSRD, GHG Protocol Corporate".
        *   **Продукт (Product)**: Иконка коробки/товара. Описание: "Углеродный след конкретного товара, CBAM, ISO 14067".
2.  **Логика**:
    *   При клике сохранять выбор (`projectType`) в стейт (или URL query param, или sessionStorage).
    *   Переход на следующий шаг (выбор шаблонов).

### 3.2. Обновленный Шаг 2: Выбор шаблонов
Файл: `src/app/projects/new/select-reports/page.tsx`

1.  **Фильтрация**:
    *   Получать `projectType` из предыдущего шага.
    *   Фильтровать список шаблонов, возвращаемый `getAllReportTemplates()`.
    *   Показывать только те шаблоны, у которых `scope === projectType` (или `both`).
2.  **Группировка**:
    *   (Опционально) Группировать отчеты по категориям (Mandatory, Voluntary, Regional) внутри списка.

### 3.3. Интеграция с API
Файл: `src/app/projects/new/select-reports/page.tsx` (функция submit)

1.  При отправке формы на `POST /api/projects` передавать:
    *   `name`: Имя проекта.
    *   `template_codes`: Массив выбранных кодов.
    *   `type`: Выбранный `projectType` (из Шага 1).

## 4. Критерии приемки (DoD)
1.  Пользователь не может начать создание проекта, не выбрав тип (Corporate/Product).
2.  Если выбран тип "Product", в списке отчетов НЕТ шаблона CSRD.
3.  Проект успешно создается в БД с правильным типом.
