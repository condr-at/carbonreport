# ТЗ-4: Dynamic Data Entry & Inputs (Ввод данных)

**Статус:** Черновик
**Дата:** 29.11.2025
**Приоритет:** Средний (Зависит от ТЗ-3)

## 1. Цель
Реализовать интерфейс ввода первичных данных ("Ингредиентов"), необходимых для расчета показателей отчетов. Интерфейс должен динамически подстраиваться под тип проекта.

## 2. Концепция "Input vs Output"
*   **Output (CSV поля):** Результаты расчетов (например, `scope1_total_co2e`). Пользователь их НЕ вводит вручную, они считаются.
*   **Input (Первичка):** То, что вводит пользователь (например, "Потребление дизеля: 500 литров").
*   **Задача:** Сделать UI для ввода Input данных.

## 3. Технические требования

### 3.1. Структура страницы проекта
Файл: `src/app/projects/[id]/...`

1.  **Адаптация меню**:
    *   Если `project.type === 'corporate'`:
        *   Меню: "Организационная структура", "Энергия (Scope 1&2)", "Цепочка поставок (Scope 3)".
    *   Если `project.type === 'product'`:
        *   Меню: "Состав изделия (BOM)", "Производственные процессы", "Логистика", "Упаковка".

### 3.2. Компоненты ввода (Input Forms)

1.  **Corporate Inputs**:
    *   **Facilities List**: Таблица филиалов/офисов.
    *   **Energy Entry**: Форма ввода потребления (Электричество, Тепло, Топливо) с привязкой к филиалу.
    *   Использовать поля из `dataset-extra-fields.json` (energy_input_amount и т.д.) как базу для полей формы.

2.  **Product Inputs**:
    *   **BOM Editor**: Таблица материалов. Колонки: Название, Вес, Страна происхождения, Тип материала.
    *   **Process Editor**: Энергия на единицу продукции.

### 3.3. Связь с Dataset
*   Все введенные данные сохраняются в соответствующие массивы внутри `project.dataset` (см. структуру "скелета" из ТЗ-1).
*   При сохранении формы обновлять JSONB в базе.

## 4. Критерии приемки (DoD)
1.  В проекте типа Corporate отображается интерфейс для ввода филиалов и энергии.
2.  В проекте типа Product отображается интерфейс для ввода состава изделия (BOM).
3.  Данные сохраняются в БД и не теряются при перезагрузке.
